Sobre a Árvore AVL

A Árvore AVL (Adelson-Velski e Landis) é uma estrutura de dados balanceada que mantém a altura da árvore mínima, garantindo operações de inserção, busca e remoção em tempo O(log n).

No seu gerenciador de tarefas, cada prioridade é armazenada como uma chave na árvore, e as tarefas com a mesma prioridade são agrupadas em listas dentro de cada nó.

Características da Nossa Implementação
  • ✓ Auto-balanceamento: A árvore se rebalanceia automaticamente após cada inserção/remoção
  • ✓ Rotações (4 casos): Left-Left, Left-Right, Right-Right, Right-Left
  • ✓ Múltiplas tarefas por prioridade: Cada nó pode armazenar várias tarefas
  • ✓ Ordenação cronológica: Tarefas com mesma prioridade mantêm ordem de criação
  • ✓ Persistência: Dados salvos em JSON e restaurados automaticamente
  • ✓ API RESTful: Integração fácil com outros sistemas via HTTP

Fluxo de Operações
1. Adicionar Tarefa

A tarefa é inserida na árvore com base em sua prioridade. Se a prioridade já existe, a tarefa é adicionada à lista do nó correspondente.

2. Calcular Fator de Balanceamento

Após cada inserção, o fator de balanceamento é calculado: altura_esquerda - altura_direita

3. Detectar Desbalanceamento

Se o fator ficar fora de [-1, 1], a árvore está desbalanceada e precisa de rotações.

4. Aplicar Rotações

As rotações rebalanceiam a árvore. Pode ser simples (um lado) ou dupla (ambos os lados).

5. Salvar Dados

Todas as tarefas são automaticamente persistidas em tasks.json.

Exemplos de Uso

Exemplo 1: Adicionar 3 tarefas com prioridades diferentes


1. Tarefa "Estudar" - Prioridade 85
2. Tarefa "Limpar casa" - Prioridade 30
3. Tarefa "Exercitar" - Prioridade 60

Resultado na árvore AVL (ordem descendente):
1. "Estudar" (85) ← Mais urgente
2. "Exercitar" (60)
3. "Limpar casa" (30) ← Menos urgente

Exemplo 2: Estrutura interna da árvore com 5 tarefas


        [60]
       /    \
     [30]   [85]
    /       /
  [15]    [70]

Onde cada número é uma prioridade.
Se houver tarefas duplicadas:
- Nó [60] pode conter: ["Tarefa A", "Tarefa B"]
Os 4 Casos de Rotação AVL

Caso 1: Left-Left (LL)

Inserção no filho esquerdo do filho esquerdo → 1 rotação à direita

Caso 2: Right-Right (RR)

Inserção no filho direito do filho direito → 1 rotação à esquerda

Caso 3: Left-Right (LR)

Inserção no filho direito do filho esquerdo → Rotação esquerda + Rotação direita

Caso 4: Right-Left (RL)

Inserção no filho esquerdo do filho direito → Rotação direita + Rotação esquerda

Dicas e Boas Práticas
  • Use prioridades bem distribuídas (não todas iguais) para maximizar os benefícios da AVL
  • Tarefas com a mesma prioridade mantêm ordem cronológica de criação
  • A altura da árvore nunca excederá 1.44 * log₂(n+1) - próximo ao logarítmico perfeito
  • Para manutenção manual do banco, edite tasks.json (validação será feita ao carregar)
  • Cada tarefa tem um ID único de 8 caracteres para evitar colisões
